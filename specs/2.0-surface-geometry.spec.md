# Lys 2.0 surface and geometry CSS

## Blueprint (Design)

### Context

Lys fits an authored slide into a browser viewport without interpreting its contents. Authors get a predictable coordinate space for layout, and presenters see the same frame shape when the window or embedding iframe changes size. This specification details the screen surface in the [approved roadmap](../docs/reports/lys-2.0-release-plan.md) and [2.0 contract baseline](2.0-contracts.spec.md).

### Architecture

**Structure and ownership.** `[data-lys]` owns the viewport backdrop. Its direct `article` children are the slide frames and CSS size containers (`container-type: size`); a nested article is ordinary authored content. No new author-facing attributes, events, tokens, or container name. The article establishes a containing block for positioned content. Container units and percentage positioning follow native CSS rules, including changes in reference caused by authored nested containers or containing blocks.

**Fit.** Let `W` and `H` be the usable physical width and height of the presentation viewport in CSS pixels and `r` the deck's width-to-height ratio. In a settled enhanced screen view the centered slide's outer frame has width `min(W, H × r)` and height `min(H, W ÷ r)`, subject to browser subpixel rounding. The viewport is that of the deck document, not the host window when embedded. The limiting axis fills the available space; unused space shows the backdrop. Both dimensions are definite and independent of descendant intrinsic sizes. Resizing the viewport (including browser zoom that changes the CSS viewport) recomputes the fit without resetting slide selection or requiring a host message. Lys does not intercept browser zoom.

**Clipping.** The article is the final paint boundary, including for fixed or absolutely positioned descendants, shadows, transforms, and elevated stacking levels. An outer viewport clip is not sufficient: it would still let oversized content paint in the letterbox. Clipping must not turn the slide frame into an engine-provided content scroller. Author-owned scroll regions inside the frame remain native. Native anchor and focus integration are separate contracts; visual clipping does not determine accessibility exposure.

**Surface defaults.** The backdrop defaults to `light-dark(#f3f6f9, #111820)`; the article defaults to `light-dark(white, black)`. The deck opts into `color-scheme: light dark` locally, so the UA can use the preferred scheme; authors can set `color-scheme` on the deck to select the scheme explicitly. The property inherits normally, including native UA scheme effects on defaults and controls. Lys does not set `color` or supply contrast pairs, typography, internal spacing, or custom control styles. Authors own foreground/background contrast and can override the slide background with ordinary CSS, including a transparent background. The engine does not set palette or scheme on the root, body, or iframe host.

**Configuration and migration.** These dispositions apply to the screen surface. Configuration is read from the deck's CSS cascade (including inherited values), not independently on each article.

| 1.2.5 surface | 2.0 surface and migration |
| --- | --- |
| `--lys-aspect-ratio` | Retain. Resolve on `[data-lys]` for every slide. A finite positive CSS `<ratio>` is accepted, including a single positive number (denominator 1). Missing, malformed, zero, negative, or non-finite ratios use `16 / 9` for the entire deck; no markup repair or error UI. Move per-article declarations to the deck. A CSS cascade change on the deck updates all frames together. |
| `--lys-backdrop` | Retain as a deck-level CSS background override, including `transparent`. Omitting it uses the default; invalid overrides follow ordinary CSS cascade and invalid-value behaviour. |
| `--lys-slide-max-width`, `--lys-slide-max-height` | Remove from screen geometry. The viewport is the bound; for an intentionally smaller presentation viewport, size the iframe in the host. |
| `--lys-slide-gap` | Remove. There is no adjustable gap between enhanced slide frames; use author CSS for spacing inside a frame. |
| `--lys-slide-padding`, `--lys-font-size-base` | Remove. Use ordinary slide/content CSS; use container-relative units when values should scale with the slide. |
| `data-background`, `data-class` | No engine interpretation. Replace with standard background declarations and `class`. |
| `--lys-focus-ring` | Not a surface setting. Do not suppress or replace native focus indicators in geometry CSS. Authors can style their own elements with ordinary CSS. |

**Integration.** `src/lys.css` owns screen sizing, clipping, and surface paint. Runtime may select slides and apply rendering state; it must not measure authored content or rewrite its CSS. None, fade, horizontal, and vertical modes use the same frame sizing and clipping; motion can move or fade a frame but does not resize it or redefine its query units. Under `prefers-reduced-motion: reduce`, an engine slide change is immediate, including any engine-driven scrolling, without disabling author animation. Transition selection and timing API (including `data-transition` migration and the duration/easing tokens) are not defined here.

Before enhancement, Lys must not impose fixed clipping or selected-slide visibility that makes authored payload unreachable. CSS-only fallback may forgo frame fidelity to preserve ordinary document-order access. Print has a different available rectangle but must preserve the same deck ratio, definite query-container dimensions, and final clip, with one complete frame per printable page. Print sizing mechanics and `--lys-print-page-size` remain separate work.

### Anti-Patterns

- Clamp width and height independently, vary ratio per article, or fit slides using the outer window's dimensions in an iframe.
- Infer the frame from content metrics, shrink text, rearrange content, open the clip to escape overflow, or apply a viewport clip in place of the article boundary.
- Set deck-level foreground, type, padding, or focus resets; reinterpret authored attributes or mutate native semantics to implement paint.
- Apply a selected-slide layout or destructive clipping before enhancement, or reuse the screen selection state to omit slides in print.

## Contract (Quality)

### Definition of Done

- The production stylesheet passes **Fit and containment**, **Ratio configuration**, and **Embedded viewport** for width- and height-constrained frames.
- **Final clip**, **Surface defaults and overrides**, and **Author ownership** verify actual clipping, colour and cascade behaviour, and the absence of engine composition defaults.
- **Motion**, **Fallback**, and **Print hand-off** verify that the geometry boundaries hold where they integrate with separate contracts.
- **Portable stylesheet** passes the CSS artifact checks in [PROJECT.md](../PROJECT.md).

### Regression Guardrails

Preserve ordinary slide markup, authored IDs, link and control semantics, and size containment. No dependencies, external stylesheet assets, author-content inspections, or accessibility claims inferred from geometry tests. Conflicting 1.x requirements in [backdrop](backdrop-color.spec.md), [container type](container-type.spec.md), [container-relative tokens](container-relative-tokens.spec.md), and [core](lys-core.spec.md) are historical for this surface, not 2.0 acceptance criteria. In particular, do not preserve default foreground/padding/type, per-slide ratios, mandatory snap layout, or content-sized print frames merely to satisfy old assertions.

### Scenarios (Gherkin)

```gherkin
Scenario: Fit and containment
  Given a deck at 16:9, 24:10, 9:19.5, or 1:1
  And slide content uses physical width and height query units with no nearer query container
  When the viewport is resized through width-limited and height-limited sizes
  Then the selected frame stays centered and matches the contain-fit dimensions
  And the selection is unchanged
  And the units resolve against the resized article, not the viewport or backdrop

Scenario: Ratio configuration
  Given the deck ratio is missing, malformed, zero, negative, or non-finite
  Then every slide uses 16:9 without rewriting the document
  When a valid positive ratio is set on the deck
  And a conflicting ratio token is set on one article
  Then every slide uses the deck ratio

Scenario: Embedded viewport
  Given a deck in an iframe smaller than its host viewport
  When the host changes only the iframe dimensions
  Then the frame refits to the iframe viewport without changing the host

Scenario: Final clip
  Given a letterboxed slide with oversized, transformed, or fixed descendants
  And a native scroll region inside the article
  When the frame is rendered
  Then the fixture paints up to but not beyond the article boundary
  And the in-slide scroll region still scrolls independently

Scenario: Surface defaults and overrides
  Given an enhanced deck with visible letterboxing and no background overrides
  When the effective colour scheme is light or dark
  Then the backdrop and slide use their specified distinct defaults
  When the author sets the backdrop token and a normal slide background declaration
  Then the respective author backgrounds win, including transparent overrides
  And styles outside the deck are unchanged

Scenario: Author ownership
  Given authored foreground and typography inherited from outside the deck
  And authored content layout and a focusable native control
  When the engine applies the enhanced geometry
  Then it adds no content padding, foreground, typography, or focus overrides
  And authored semantics and focusability are unchanged

Scenario: Motion
  Given any supported deck transition style and reduced motion requested
  When the selected slide changes
  Then the destination frame is presented immediately at its settled fit
  And author animations are not suppressed by Lys

Scenario: Fallback
  Given the stylesheet is loaded but JavaScript is disabled
  And authored payload uses normal flow and would exceed the enhanced frame
  When reading and scrolling the document
  Then the engine has not hidden any of that payload
  And every slide is reachable in document order

Scenario: Print hand-off
  Given a selected slide in a deck with a non-default ratio and intentional edge clipping
  When the browser prints the presentation
  Then every slide prints in document order, one complete frame per printable page
  And the frame ratio, container-relative composition, and intentional edge clip are preserved

Scenario: Portable stylesheet
  Given a fresh production build
  Then dist/lys.css has no external imports or asset references
  And its minified gzip size is below 2,000 bytes
```
